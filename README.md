# 小星 · 家庭儿童 AI 小助手

一个**单文件网页应用**，给家里任意多个孩子用（首次预置**阳阳 7 岁**、**哈宝 13 岁**，可随时增删改）。覆盖问问题、学习辅导、讲故事、情绪倾听和每日小任务。语气与内容分级按年龄自动分四档（≤8 / 9–12 / 13–15 / 16+），不写死。所有记录默认只存在当前设备；只有你主动配置同步地址或在线模型时，才会按下文范围发出数据。

**身份说明（重要）**：小星**不做声纹、也不做人脸识别**，不会判断「现在坐在这里的是谁」。所谓「谁在用就切到谁」靠两件事：**这台设备绑定给哪个孩子**，以及**上次使用的是谁**；此外首页常驻头像条可以一键切换。

> 小星是**辅助工具**，不能让孩子更健康、情绪更好，也不能替代家长的陪伴与判断。出现自伤、被霸凌、离家出走等信号时，请家长立即介入。

## 二、第一次打开（约 3 分钟）

1. 双击 `index.html`，或在 iPhone 的「文件」App 中点开。
2. 首次设置已预填 **阳阳 / 7 岁** 和 **哈宝 / 13 岁**；不对就直接改，完成后点「开始」。更多孩子之后在「家长端 → 孩子」里添加。
3. 进入首页。头像条列出所有孩子，点一下即切换；每个孩子有自己的聊天、模式、记录、时长和积分。
4. 没有填 API Key 时，页面顶部会显示「未配置模型，当前为离线小模式」——这时也能完整使用内置问答、讲题思路、故事和情绪回应。

昵称、年龄、头像、口令、时长、禁聊都在「家长端 → 孩子」修改，保存后立即生效。程序按年龄分四档：`≤8`、`9–12`、`13–15`、`16+`；语气、回答长度、安全策略、默认时长都会跟着变。详见第十五节。

## 三、四个年龄档的差异

| 项目 | ≤8 岁（小朋友档） | 9–12 岁（小学生档） | 13–15 岁（少年档） | 16+ 岁（青少年档） |
| --- | --- | --- | --- | --- |
| 称呼与语气 | 短句、具体、多比喻 | 清楚、具体、带一点原理 | 平等、不幼稚、讲原理与边界 | 完整、可讨论、区分事实与推断 |
| 回答长度（离线兜底） | 约 2 句 + 一句邀请 | 约 3 句 + 一句延伸提示 | 最多 6 句 + 两句背景 | 最多 9 句 + 依据与边界说明 |
| 模式入口 | 问为什么、学本领、听故事、说心情 | 问问题、讲题、学习方法、聊心事 | 问问题、讲题、学习方法、聊心事 | 问问题、讲题、学习方法、聊心事 |
| 性教育/身体变化 | 不展开，温和转给家长 | 基础科学词汇、卫生与自我保护，建议问家长；不展开成人内容 | 科学、适龄、不回避，并提示「也可以和爸妈聊」 | 可讲完整生理与同意/界限/法定年龄，不给操作细节 |
| 家长可见性 | 默认全量可见 | 默认全量可见（可开「须知同意」） | 默认开启「须知同意」：只看摘要 + 风险提醒 | 默认开启「须知同意」：只看摘要 + 风险提醒 |
| 默认每日上限 | 30 分钟 | 45 分钟 | 60 分钟 | 90 分钟 |
| 默认禁用时段 | 20:30–07:00 | 21:00–06:30 | 22:00–06:30 | 23:00–06:00 |
| 睡前模式 | 禁用前 30 分钟改为故事时间 | 无 | 无 | 无 |

同一句「为什么天是蓝的」，5 / 9 / 14 / 17 岁会得到不同长度和措辞的答案：5 岁只讲两三句并邀请想一想；9 岁先结论再解释并给查法；14 岁补背景与例外；17 岁分结论、依据、边界，并用「主流解释」这类限定词。14 岁不会拿到 7 岁的语气。

### 对话没有范围限制（重要）

四个模式只是**快捷入口和引导语**，不是沟通边界。点了「听故事」也可以直接问算术，点了「聊心事」也可以问宇宙；孩子随时换话题，不需要先切模式。系统提示里不设话题范围，唯一会避开的是：

1. **安全护栏**：自伤、暴力、色情、危险物品、隐私、健康诊断；
2. **家长自设的禁聊清单**（家长端「禁聊清单」里填写的词）。

除此之外一律正常回答。离线模式下，内置知识只是优先命中；没有命中时会给诚实、适龄的回应（7 岁说「我知道一点点」并一起猜/找证据，13 岁承认不确定并说明可以从课本、原始来源、老师或家长那里查），**不会用拒答话术把孩子推走**。孩子说「不想聊」时，小星不追问，只回一句「好，那我们先不说，你想聊的时候再找我」。

家长端的话题分布只是**统计标签**，不限制提问；没有命中任何分类的会记为「其他」。

### 须知同意（按孩子开关，重要）

- 「须知同意」现在是**每个孩子单独**的开关（在「家长端 → 孩子」里设置），不再用年龄硬编码；默认 ≤12 岁关闭、≥13 岁开启。
- 开启的孩子，首页有一张「你的对话，爸妈能看到什么」卡片，明确告诉孩子：**爸妈默认看不到聊天原文，只看到时长、主题和风险提醒；出现危险信号会立刻提醒自己去找他们，配置了同步时也会通知他们。**
- 孩子可以自己开关「允许爸妈查看聊天原文」，默认关闭。
- 家长端默认「完全可见」也是关闭的。
- **只有两个开关都打开**（家长在设置里开启 + 孩子在自己页面同意），家长端才会出现这个孩子的逐句原文。
- 风险事件（自伤、被霸凌、离家出走等）**不受这两个开关限制**：孩子端一定出现求助提示，本机一定留痕；配置了同步地址时立即上报。默认只上报风险类型和时间，不上报原话。
- 孩子随时可以关掉同意；关掉后家长端立即恢复为摘要模式。

## 四、接入大模型（可选）

### 先看核查结论：Qoder / WorkBuddy 能不能当模型供应商

**结论：网页不能直连它们，但可以经本目录的 `server/` 代理间接使用。** 「OpenAI 兼容」仍是最简单的直连方式；WorkBuddy 与 Qoder 走代理后可用（Qoder 需家长 PAT）。

| 名称 | 已核实的事实 | 对本页的结论 |
| --- | --- | --- |
| **Qoder**（qoder.cn） | 官方 Qoder Agent SDK（`@qodercn-ai/qodercn-agent-sdk`，TypeScript，Node ≥18）可用 Personal Access Token 调用；它是 **Agent 运行时**，不是裸聊天 API，会启动 `qoderclicn` 进程 | **不能由浏览器直连**；已在本项目 `server/` 的 `qoder` 通道实现，需 PAT |
| **WorkBuddy**（腾讯云，CodeBuddy 系） | 官方文档写明它是桌面 AI 智能体；可在「设置 → 模型 → 自定义」里填 TokenHub 的 OpenAI 兼容地址 `https://tokenhub-intl.tencentcloudmaas.com/v1/chat/completions` + 腾讯云 API Key；浏览器直连预检返回 405，无 CORS 头 | **只能服务端转发**；已在 `server/` 的 `workbuddy` 通道留出代码路径，**端点与鉴权待凭证验证** |
| **通用 OpenAI 兼容** | `POST {Base URL}/chat/completions` + Bearer Key；能否跨域取决于服务商 | **可用**（需服务商允许 CORS，或同样走代理） |

实测依据（2026-11-04）：

- 对 WorkBuddy 文档给出的 TokenHub 地址发跨域预检 `OPTIONS`，返回 **405**，且没有 `Access-Control-Allow-Origin`——浏览器会直接拦截，网页端填了也调不通。
- Qoder 的公开文档 `docs.qoder.cn/cli/sdk/overview` 给的是 **SDK / CLI 形态**（PAT、Service Account 或本机登录态），没有面向浏览器的推理端点。
- **未能核实**：TokenHub 是否存在允许浏览器跨域的其他区域端点；如果「WorkBuddy」指其他同名产品，其能力无法核实——上表结论针对腾讯云 CodeBuddy 系的 WorkBuddy。若你拿到官方书面接口文档，可直接按「通用 OpenAI 兼容」填进来试。

### 代理模式（推荐用于 Qoder / WorkBuddy）

`server/` 是一个本机小服务，把真实 Key / PAT 留在电脑上，网页只拿一个代理令牌。一个代理可以同时服务三个通道（请求带 `X-Provider`）。

### 模型通道怎么选、怎么填凭证、怎么设主备

网页「家长端 → 设置 → 模型接入」现在有四个连接方式：

| 连接方式 | 网页要填什么 | 凭证放哪 | 能力说明 |
| --- | --- | --- | --- |
| **Qoder** | 代理地址 + 代理令牌 + 模型档位 | 服务端 `.env` 的 `QODERCN_PERSONAL_ACCESS_TOKEN`（PAT） | 仅 `auto / ultimate / performance / efficient / lite` 五档；单轮独立会话（多轮由前端拼接最近 10 条消息）；PAT 不会自动刷新，换 PAT 后需重启代理 |
| **WorkBuddy** | 代理地址 + 代理令牌 + 模型名（可留空） | 服务端 `.env` 的 `WORKBUDDY_BASE_URL` / `WORKBUDDY_API_KEY` | 走服务端端点；使用 Bearer 还是 AK/SK 需与服务端确认，网页端一律不填厂商凭证 |
| **OpenAI 兼容** | Base URL + API Key（或代理令牌）+ 模型名 | 可直连放本机，或放服务端 | 任何 `/chat/completions` 端点；跨域由服务商决定 |
| **离线模式** | 不用填 | 无 | 内置内容，不联网，始终可用 |

设置步骤：

1. 在 `server/` 执行 `npm install`（Qoder 通道需要官方 SDK），复制 `.env.example` 为 `.env`，填 `PROXY_TOKEN` 和你要用的通道凭证；
2. 启动：`node server.mjs` 或双击 `start.bat`（默认 `http://127.0.0.1:8787`）；
3. 在设置页填每个通道的**代理地址**（如 `http://127.0.0.1:8787/v1`）和**代理令牌**（就是 `PROXY_TOKEN`，不是厂商 Key）；
4. 每个通道都有「测试连接」按钮：成功显示「连接成功」，失败会给出可读原因——鉴权失败（401）、跨域/网络不可达、超时、通道未配置（501）等；
5. 在主通道下拉里选 Qoder / WorkBuddy / OpenAI 兼容 / 离线；在备用通道里再选一个。主通道出现 **401 / 403 / 429 / 超时 / 5xx** 时会自动切备用，孩子端不显示任何技术错误，只给一句友好提示；切换事件与原因会记在家长端设置页（最近 6 条）。
6. 没填完整凭证的通道在下拉里显示「未配置」且不可选，避免点到必然失败的选项。

详细凭证、环境变量、错误码与「已实测 / 待验证」清单见 [`server/README.md`](../server/README.md)。

> 孩子手机上**不要**填厂商 Key 或 PAT。令牌泄了就在 `.env` 里换一个新的并重启。Qoder 的 PAT 只在服务端，网页端永远填不到。

### 直连填法（仅 OpenAI 兼容）

在「家长端 → 设置 → 模型接入」填写三项：

| 字段 | 说明 |
| --- | --- |
| Base URL | OpenAI 兼容接口地址，**写到 `/chat/completions` 之前**，例如 `https://api.deepseek.com/v1` |
| API Key | 服务商密钥，只保存在本机 `localStorage` |
| 模型名 | 服务商控制台里的模型名，不是产品名 |

常见服务的 Base URL 形态（模型名以服务商当前文档为准）：

- DeepSeek：`https://api.deepseek.com/v1`
- 火山方舟（豆包）：`https://ark.cn-beijing.volces.com/api/v3`，模型名通常填推理接入点 ID（`ep-...`）
- Kimi / Moonshot：`https://api.moonshot.cn/v1`
- OpenAI：`https://api.openai.com/v1`

填好后点「测试连接」。成功会提示「连接成功」，失败会给出中文原因。

### 在线模式的行为

- 使用 `POST {Base URL}/chat/completions`，`Authorization: Bearer {Key}`。
- 默认流式输出（SSE），文字逐段出现；30 秒无响应会中止。
- 主通道失败（401 / 403 / 429 / 超时 / 5xx）时自动切备用；孩子端只看到一句友好提示，不会看到状态码、Key、CORS 或超时字样；家长端设置页记录切换事件与原因。
- 系统提示词会按年龄档、入口、护栏结果动态生成；入口只是引导语，不限制话题。四档句数上限为 2 / 3 / 6 / 9 句，13 岁以上禁止说「你还小」、禁止代替家长做决定。
- 在线模式下，**当前问题和最近 10 条对话会发送给所选服务商**。这是使用在线模型的必要代价，详见「隐私与数据」。

### 跨域（CORS）提示

浏览器是直连服务商的。如果服务商不允许网页跨域，会看到「网络或跨域受限」的友好提示。解决办法：

1. 换支持 CORS 的服务商或网关；
2. 自建一个很小的转发服务（服务端转发，Key 放服务端）；
3. 部署到 https 静态站点后再试（有些服务商只允许特定来源）。

不要为了绕过跨域把 Key 写进公开网页。

### 离线模式能做什么

- 7 岁：15 组「为什么」、口算/拼音/写字/看图说话引导、情绪命名、5 个主题故事。
- 13 岁：信息辨别、AI 使用边界、数学/物理/英语/作文思路、错题复盘、学习方法、同伴与情绪话题、青春期身体变化的科学回答。
- 离线回答是模板化的，**不能覆盖所有问题**；没有命中时会给诚实、适龄的回应：7 岁说「我知道一点点」并邀请一起找证据，13 岁承认不确定并说明可以从课本、原始来源、老师或家长那里查。不会拒答，也不会要求孩子换话题。

## 五、iPhone / iOS Safari 适配

### 1. 布局

- 按 375–430px 宽度设计；已测 375、390、430 三档，首页和聊天页均无横向滚动。
- `viewport-fit=cover` + `env(safe-area-inset-*)`，刘海和底部横条区域留白。
- 输入框聚焦时监听 `visualViewport`，调整聊天区高度并把最新消息滚到可见位置，避免键盘遮挡。
- 已加入 `apple-mobile-web-app-capable`、`apple-mobile-web-app-status-bar-style`、`apple-mobile-web-app-title`。

### 2. 添加到主屏幕

1. Safari 打开页面。
2. 点底部「分享」。
3. 选「添加到主屏幕」，名称可改为「小星」。
4. 以后从主屏幕图标打开，界面更接近全屏。

注意：`file://` 打开的页面无法从主屏幕获得完整的独立窗口体验，建议用 https 部署后再添加。

### 3. 朗读（TTS）

- 聊天页右上角有「朗读开/关」，默认关闭；打开后新回复会尝试自动朗读。
- 每条机器人消息下方还有单独的「朗读」按钮。
- **iOS 不允许无用户手势的自动播放**。第一次一定要由孩子或家长点击「朗读」或「朗读开」；之后系统仍可能拦截，最稳的是点每条消息下的「朗读」。
- 浏览器不支持 `speechSynthesis` 时，右上角开关会隐藏；点消息下的「朗读」会提示「这台设备的浏览器不支持朗读」。
- 朗读依赖系统中文语音包。若没声音：检查静音开关、音量，并在「设置 → 辅助功能 → 朗读内容 → 声音」里下载中文语音。

### 4. 语音输入（可选）

- 使用浏览器 `SpeechRecognition` / `webkitSpeechRecognition`。
- iOS Safari 要求 **https 或 localhost**；`file://` 本地打开时通常不可用，按钮可能仍显示但识别会失败。
- 不支持或权限被拒时，按钮会隐藏或给出提示；**不用语音也能完整使用**，键盘输入是主路径。

### 5. 本地存储风险

- 数据保存在 Safari 的网站数据里。以下情况会丢失：
  - 设置里「清除历史记录与网站数据」；
  - 长期不使用被系统回收；
  - 无痕/隐私浏览模式；
  - 换手机、换浏览器、换访问地址（`file://`、局域网 IP、https 域名各自独立）。
- 建议每周在「家长端 → 数据」导出一次备份，存到「文件」App 或微信收藏。
- 备份**不包含 API Key**；导入后需重新填写 Key。导入改为**按 childId 合并**：新孩子新增，已有孩子补数据并去重，不会覆盖其他孩子；仍建议导入前先导出旧数据。

### 6. `file://` 本地打开时受限的功能

| 功能 | `file://` 表现 |
| --- | --- |
| 离线问答、故事、任务、家长端 | 正常 |
| 在线模型 | 部分服务商因 `Origin: null` 拒绝跨域，可能失败并自动降级离线 |
| 麦克风语音输入 | 通常不可用（非安全上下文） |
| 自动朗读 | 可能受手势限制；点「朗读」按钮更可靠 |
| 添加到主屏幕 | 体验不完整 |
| 数据持久性 | 可用，但更容易随文件移动或系统清理丢失 |

要让在线模型和麦克风稳定工作，请用 https 静态托管（见下一节）。

## 六、三种部署路径

### 路径 A：本地直接打开

适合先试用。

1. 把 `index.html` 放到一个固定文件夹。
2. 双击，或 iPhone「文件」App 中点开。
3. 缺点：在线模型可能被 CORS 拦截，麦克风通常不可用。

### 路径 B：局域网访问（同一 Wi-Fi）

适合家里临时给平板/手机用，不需要域名。

1. 电脑安装 Python 3。
2. 在 `index.html` 所在目录打开终端：
   ```bash
   python -m http.server 8000 --bind 0.0.0.0
   ```
3. 查电脑局域网 IP（Windows：`ipconfig`，看 IPv4）。
4. iPhone 与电脑连同一 Wi-Fi，Safari 打开 `http://电脑IP:8000/index.html`。
5. 注意：这是 http，不是 https；麦克风仍不可用，在线模型仍可能被 CORS 拦。电脑关机后地址失效。

### 路径 C：静态托管（推荐长期使用）

任选其一：GitHub Pages、Cloudflare Pages、Vercel、对象存储静态网站等。

1. 新建一个仓库/项目，只上传 `index.html`（和两个说明文档可选）。
2. 开启静态站点，得到 https 地址。
3. iPhone Safari 打开，按第五节「添加到主屏幕」。
4. https 下麦克风可用（首次会请求权限）；在线模型仍取决于服务商是否允许该来源跨域。

不要上传任何含有真实 API Key 的备份 JSON。

## 七、同机模式与分机模式

程序**没有账号系统，也没有默认的云端同步**。只有你在设置里填写了「同步地址」并打开自动上报，摘要与风险类型才会 `POST` 到那个地址；不填就完全留在本机。

### 同机模式（默认）

家长手机给孩子用，孩子端和家长端在同一个 `index.html` 里：

1. 孩子用完，点右上角「家长」。
2. 输入算术题答案，或家长在设置里设的 4 位 PIN。
3. 进入家长端看摘要、风险提醒、设置时长和禁用时段。
4. 关闭家长端，回到孩子首页。

适合多个孩子共用一台设备：可绑定一个默认使用者，也可在首页头像条一键切换（设了口令的要输口令）。

### 分机模式（孩子各一台 iPhone）

每个孩子各用一台、家长用另一台时，优先用**自动上报**，摘要卡是兜底。程序**不做云账号，也不假装自动云同步**。

#### 方式 A · 自动上报（推荐）

1. 家长在**每台孩子手机**的「家长端 → 设置 → 分机同步」填同一个 **HTTPS 同步地址**（可选填令牌）。
2. 勾选「自动上报今日摘要与风险」，点「发送测试摘要」确认端点收到。
3. 之后：每次孩子聊完（最多 2 分钟一次）、页面切到后台、以及**出现高风险信号时立即**，App 会 `POST` 一份 JSON 到该地址。
4. 家长在自己的手机/电脑上查看该地址收到的数据（App 本身不提供远程查看界面）。

上报的字段（**不含聊天原文**）：

```json
{
  "app": "kids-ai-helper", "schema": 4, "kind": "daily | risk | test",
  "date": "2026-11-04", "sentAt": "2026-11-04T12:00:00.000Z",
  "childId": "k7",
  "kid": { "id": "k7", "name": "阳阳", "age": 7, "level": "little", "band": "小朋友档" },
  "usage": { "messages": 12, "minutes": 8, "limitMinutes": 30 },
  "topics": ["情绪", "故事"],
  "tasks": { "done": 1, "total": 3 },
  "risks": [{ "level": "high", "type": "离家出走", "ts": 1793780530411 }],
  "note": "仅摘要与风险类型，不含对话原文"
}
```

风险事件额外带 `kind: "risk"` 与 `risk.type`。**永远不上传** `messages` 原文、聊天记录、API Key、同步令牌。

失败时不会打扰孩子，只在家长端「设置」里显示「上次上报失败（网络或跨域失败）」，摘要卡仍然可用。

#### 方式 B · 手动摘要卡（兜底）

1. 孩子在首页点「生成今日摘要卡」。
2. 卡片只含：`childId`、昵称、年龄、年龄档、日期、对话条数、使用分钟、常聊主题、任务与积分、风险提醒条数和高优先级数量、信号类型。**不含聊天原文。**
3. 点「复制」或系统「分享」，通过微信/AirDrop 发给家长。
4. 家长在自己手机的「家长端 → 分机」粘贴，点「查看」，保存在本机「最近导入」。

限制：

- 摘要卡不会自动更新；孩子可以选择不发。
- 自动上报依赖你自建的端点，**App 不保证送达**；高风险信号仍要家长平时留意和主动沟通。
- 没有配置同步地址时，风险事件只在孩子手机上提醒孩子找家长，并在「家长端 → 分机」留痕（可随备份导出）。

#### 7.3 零成本可落地的同步方式

**最省事：Cloudflare Workers 免费版 + KV/D1（或直接转发到飞书/企微群机器人）。**

```js
export default {
  async fetch(req, env) {
    if (req.method === 'OPTIONS') {
      return new Response(null, { status: 204, headers: {
        'Access-Control-Allow-Origin': 'https://你的页面域名',
        'Access-Control-Allow-Methods': 'POST, OPTIONS',
        'Access-Control-Allow-Headers': 'content-type, authorization'
      }});
    }
    if (req.method !== 'POST') return new Response('no', { status: 405 });
    const auth = req.headers.get('authorization') || '';
    if (auth !== 'Bearer ' + env.SYNC_TOKEN) return new Response('forbidden', { status: 403 });
    const data = await req.json();
    // 只存摘要；建议 90 天后清理
    await env.KIDS_KV.put(`log:${Date.now()}`, JSON.stringify(data), { expirationTtl: 86400 * 90 });
    // 可选：高风险时转发到飞书/企微机器人（需按它们的消息格式包一层）
    return new Response('{"ok":true}', { headers: {
      'Access-Control-Allow-Origin': 'https://你的页面域名',
      'Content-Type': 'application/json'
    }});
  }
};
```

- 绑定 KV 命名空间，设环境变量 `SYNC_TOKEN`，部署后把 Worker 地址填入 App。
- 免费额度足够两个孩子每天几十条摘要。
- 不想写代码：用支持「自定义 JSON Webhook」的自动化平台（如 n8n、Make、Zapier）接收并写入表格；飞书/企微群机器人接收的是它们自己的消息格式，不能直接把本程序的 JSON 丢进去，需要中间转一层。
- 也可以把 Worker 换成任意你信任的 HTTPS 函数（腾讯云函数、阿里云 FC、Vercel、Zeabur 等）。

#### 7.4 隐私与合规取舍

- **默认不上传原文**：同步只发摘要、主题和风险类型。风险原话只留在孩子设备的 `localStorage`，家长导出备份时才可能看到（备份本身是家长主动操作）。
- **主题也可能敏感**：即使没有原话，「情绪」「身体变化」这类主题也能推测状态。请把端点放在自己可控的账号下，设置访问令牌，限制保留时间。
- **合规**：不满 14 周岁儿童的个人信息属于敏感个人信息。请以监护人身份配置，只收集必要字段；不要指向不明第三方的公开 Webhook；使用境外服务时注意数据出境要求。
- **令牌安全**：同步令牌和 API Key 一样只存本机，导出备份时会自动清空。泄露后立即在服务端换令牌。
- **谁能看**：13 岁的分级可见逻辑在 App 内生效，但同步端点收到的 JSON 是给家长的——请不要把端点地址或令牌告诉孩子，也不要把原始 JSON 转发到公开群。

## 八、隐私与数据说明

### 存在哪里

- 全部数据在浏览器 `localStorage`，键名 `kids_ai_helper_v2`。
- 包括：所有孩子档案（含已归档）、聊天记录（每个模式最多保留 120 条）、每日统计、习惯与积分、使用分钟、家长设置、按孩子的「须知同意」、PIN、同步地址与令牌、高风险事件留痕。
- 没有账号系统，没有分析埋点，没有自动上传。

### 什么时候会离开设备

- **在线模型模式**：当前问题 + 最近 10 条对话 + 系统提示词会发送给你填写的模型服务商。服务商如何保存、是否用于训练，取决于其条款。
- **配置了同步地址**：每次聊完、切到后台、出现高风险时，发送一份摘要 JSON（昵称、年龄、时长、主题、任务、风险类型），**不含聊天原文**。地址由你填写，程序不预设任何第三方端点。
- 未配置同步、使用离线模式时：任务、家长端、摘要卡、备份都不联网。

### Key 与同步令牌的安全

- API Key 和同步令牌都以明文存在本机 `localStorage`。
- 建议单独申请一把**低额度、可随时撤销**的 Key；同步令牌用随机长字符串，并只放在自己的服务端环境变量里。
- 不要把 Key / 令牌截图、发群、写进公开仓库，也不要把带令牌的同步地址给孩子。
- 导出备份已自动去掉 Key 和同步令牌；但聊天记录、昵称、情绪信号、风险留痕仍在备份里，备份文件也要当隐私文件保管。

### 孩子隐私

- 系统提示词明确要求不索取真实姓名、学校、住址、电话。
- 孩子主动说出这类信息时，界面会提醒「不要放在聊天里」。
- 家长端能看到的内容因年龄而异：7 岁全量；13 岁默认摘要 + 风险提醒。

### 删除数据

「家长端 → 数据 → 清除这台设备上的全部数据」会删除聊天、任务、设置和 Key，不可恢复。清除前先导出。

## 九、安全护栏与边界

### 触发分层

1. **危机**：自伤、自杀、不想活等 → 立即停止正常回答，显示「请现在去找爸爸妈妈/老师」，记录高优先级事件。
2. **13 岁高风险**：被霸凌、被威胁、想离家出走、自我指涉的抑郁/不想上学 → 停止正常回答，给具体求助步骤，高优先级通知家长。
3. **7 岁离家出走** → 危机卡 + 通知家长；7 岁「被欺负/害怕/难过/不想上学」→ 正常安抚 + 家长端标红 + 介入建议。
4. **家长禁用话题** → 温和避开，建议等家长在时一起聊。
5. **隐私信息**（姓名、学校、住址、电话、手机号）→ 提醒不要透露。
6. **暴力、色情、成人内容、烟酒药品、危险物品** → 不给做法，转给家长。
7. **性教育与身体变化**：13 岁给科学回答并提示可和爸妈聊；7 岁温和回避。
8. **健康类**：不诊断、不开药、不替代医生。

护栏是**关键词 + 规则**，不可能覆盖所有表达。孩子可能用错别字、暗语、反讽绕过；在线模型也可能生成不合适内容。家长仍需定期查看（7 岁）或定期沟通（13 岁）。

### 哪些事不该交给 AI

- **诊断和用药**：发烧、过敏、心理疾病、药物剂量——问医生，不问小星。
- **法律纠纷**：校园冲突升级、赔偿、报警、监护权——找律师/学校/相关部门。
- **替孩子做重大决定**：转学、休学、惩罚、和谁断绝来往、要不要报警。
- **急性危机**：自伤、走失、被威胁、家暴——先保证安全，联系家长/老师/医生，必要时 110/120。
- **真实个人信息**：姓名、学校、住址、电话、身份证、照片。
- **需要长期陪伴的情绪问题**：AI 可以陪聊，但不能替代父母的倾听和专业心理支持。

## 十、常见问题（FAQ）

**Q1：打开是空白/没有样式？**
确认文件完整、用 UTF-8 保存、浏览器允许 JavaScript。不要用记事本另存成 ANSI。

**Q2：为什么发消息没反应？**
看是否到了每日上限或禁用时段（输入框会禁用并显示提示）；看是否在回复中（发送按钮短暂禁用）。

**Q3：显示「未配置模型」是坏了吗？**
不是。离线小模式可完整使用，只是回答来自内置内容，不会实时生成。

**Q4：在线模式报「Key 不对/被限流/地址不对」？**
按提示让家长检查。401/403 多为 Key 或权限；429 为限流，等一两分钟；404 多为 Base URL 或模型名错。任何错误都会自动降级离线。

**Q5：13 岁家长端为什么看不到原文？**
默认设计如此。需要家长在设置开启「完全可见」，且孩子在首页打开「允许爸妈查看聊天原文」，两者同时满足。

**Q6：孩子把同意开关关了怎么办？**
这是设计的一部分，孩子有否决权。家长应通过沟通而不是技术绕过。风险事件不受影响：孩子端一定弹出求助提示并在本机留痕，配置同步时另发一条 `risk` 摘要。

**Q7：分机模式为什么没收到上报？**
先看「家长端 → 设置 → 分机同步」的状态：没填地址就不会上报；填了但显示「失败」，多为 https/CORS、令牌不对或端点没写 `OPTIONS` 预检。点「发送测试摘要」可即时排查。没有同步地址时，用摘要卡兜底。

**Q8：换手机/换地址后记录没了？**
`localStorage` 按来源隔离。用导出 JSON → 新设备导入恢复；Key 需重填。

**Q9：朗读没声音？**
iOS 需用户点击触发；检查静音开关、媒体音量、中文语音包；优先点消息下方「朗读」。

**Q10：麦克风按钮不见了？**
浏览器不支持、非 https/localhost、或权限被拒。键盘输入不受影响。

**Q11：修改年龄后模式变了？**
按年龄分四档：`≤8`、`9–12`、`13–15`、`16+`。改年龄会切换整套语气、回答长度、安全策略和默认时长，历史记录保留。

**Q12：能把 PIN 告诉孩子吗？**
不建议。PIN 是家长端锁；孩子知道就失去分级意义。算术题也只是一道轻量门槛，不是安全认证。

**Q13：数据会被服务商看到吗？**
只有在线模式会把当前问题和最近对话发给服务商。离线模式不联网。详见第八节。

**Q14：可以给别的家庭用吗？**
可以复制文件，各自的数据互不影响。请同时阅读免责声明，并按自家孩子年龄重设。

**未在真机 iPhone Safari 上验证**：Windows 上的 Edge headless 能覆盖 DOM 逻辑与 CORS，但安全区、键盘弹起、`SpeechSynthesis`、`getUserMedia`（麦克风）、私有模式下 localStorage 不可用这些 iOS 专属行为需要在真 iPhone Safari 上走一遍。完整的可勾选清单见 ARCHITECTURE.md 第 8.5 节，下面列核心要点：

- **安全区（1–3 步骤）**：iPhone 14 Pro 及以上的灵动岛 / 底部 Home Indicator 不遮挡头像条、聊天页输入框、家长端底部按钮；横屏时内容自动避开安全区。
- **键盘弹起（4–5 步骤）**：iOS Safari 键盘弹起异步、不触发 `resize`；聊天页输入框被软键盘推出视野后能自动滚回；家长端表单点击输入框不被键盘盖住"记录这笔积分变动"按钮。
- **TTS 自动朗读（6）**：iOS Safari 要求 `SpeechSynthesis` 必须由用户手势触发（如按钮点击）才发声；已实现为点击气泡朗读；验证长按 / 自动朗读（如果开启）在真机上不被拦截。
- **麦克风（7）**：iOS Safari `getUserMedia` 仅 HTTPS，`file://` 完全不工作；验证真机首次使用是否弹权限框、拒绝后是否静默降级。
- **私有模式（8）**：开启 Safari 私有模式后 localStorage 抛 SecurityError；验证页面不崩溃、给出可读提示。
- **分机同步 fetch（9）**：iOS Safari 跨域 fetch 更严格；验证 OPTIONS 预检 404 时 fetch 不会静默卡住。
- **自动化脚本入口**：仓库根目录 `test-ios-device.mjs` 覆盖 A1–A4 / B1–B3 / C1–C2 / F1 / G1–G2 / H1 共 14 项可自动判定项，其余 9 项（锁屏、录音权限、私有模式、CORS 失败、长时间切后台）会以 `SKIP` 列出需人工复核。Windows 上先跑 `node test-ios-device.mjs --dry-run` 做本机预检；真机有两条路——① 本机 Appium（需 Mac，设 `APPIUM_URL` / `IOS_UDID`）；② 云真机（`CLOUD=browserstack` + `BS_USER` / `BS_KEY`，或 `CLOUD=lambdatest` + `LT_USER` / `LT_KEY`），Windows 可直接跑。两种方式都必须提供公网 HTTPS 的 `APP_URL`。

## 十二、正式启用前，建议家长确认

1. 所有孩子的**昵称**（默认阳阳 / 哈宝）与**年龄**（默认 7 / 13），在「家长端 → 孩子」核对；不需要的孩子可以归档删除，缺的可以新增。昵称不必真实姓名，年龄决定语气档、默认时长与安全策略。
2. **设备安排**：同机还是分机（每个孩子一台 iPhone + 家长一台）。分机时在每台孩子设备上点「家长端 → 孩子 → 设为这台设备默认」，一台设备只绑一个孩子。请先准备：
   - 一个 **HTTPS** 同步地址（Cloudflare Worker / 云函数 / 自动化平台 webhook 均可，需支持 `POST` + `OPTIONS` 预检）；
   - 可选一个随机长令牌（服务端校验 `Authorization: Bearer ...`）；
   - 一个你能在家长手机上查看该地址数据的方式（后台、表格、群机器人通知等）。
   - 都不方便时，退回「摘要卡」即可，不必勉强配置。
3. **是否有可用的大模型 API Key**：没有也能用离线模式。直连需要 Base URL、Key、模型名，并确认服务商允许网页跨域；**Qoder / WorkBuddy 请走 `server/` 代理**（Qoder 需在 <https://qoder.cn/account/integrations> 创建 PAT，WorkBuddy 需腾讯云控制台的 Key，端点以控制台为准）。详见第四节与 `server/README.md`。
4. **每日上限与禁用时段**：默认按年龄档 30 / 45 / 60 / 90 分钟，可在「孩子」页逐个调整。
5. **家庭约定**：和孩子说清楚哪些可以问、哪些要找人、「须知同意」和口令怎么用；分机时要和孩子说「会上报摘要，但不上传聊天原文」。
6. **真机 5 分钟验收**：
   - 添加主屏幕；
   - 切换孩子，改一次昵称和年龄再改回，确认首页文案与语气档跟着变；
   - 给一个孩子设 4 位口令，确认切换时要求输入；清空口令后确认直接切换；
   - 5 岁与 14 岁各问一次「为什么天是蓝的」，确认答案长度和措辞不同；
   - 发一句「我不想活了」，确认危机卡出现；再到「家长端 → 分机」确认有高风险留痕；
   - 分机：在一台设备上绑定孩子 → 填同步地址 → 点「发送测试摘要」，确认端点收到 `kind: "test"` 和 `childId`；
   - 家长端进入，确认开启「须知同意」的孩子默认看不到原文；
   - 导出一次备份，确认文件里有所有孩子且没有 API Key / 同步令牌；再导入同一个文件，确认记录没有翻倍。

## 十四、积分、习惯与 AI 预审（v3）

### 1. 一套计分，不再有第二套

旧的「星星」在首次加载时**一次性并入积分**（1 星 = 1 分），并入后 `stars` 字段被整体移除，界面、备份和同步里都不再出现第二套计分。迁移在 `ensureKid` 内、补默认值之前执行，避免旧值先被补成 0 而丢失。

新增存储字段（都在同一个 `localStorage` 键 `kids_ai_helper_v2` 内，随备份一起导出）：

- `points / frozen / pointLog / bonus`：积分余额、冻结、流水、当日加时；
- `habitDefs / habitLog`：习惯定义与每日记录（含 AI 结论文档）；
- `rewardDefs / redemptions / unlocks`：奖励库、兑换申请、已解锁内容；
- `pointsCfg`：每日上限、确认阈值、每个孩子的审核模式、关键习惯、最近可信时间、异常记录；
- `aiStats`：AI 自动通过数与撤销数（用于准确率）。

导入旧备份时，`loadState()` 会做嵌套合并并补齐缺失字段；旧 `tasks` 保留为习惯完成数，旧 `stars` 若仍在备份中，会按同一规则并入后丢弃，不会报错，也不再驱动界面。

### 2. 防刷分

- `日期 + 习惯 ID` 唯一：同一习惯同一天只能提交一次；
- 每日积分上限（默认 30，可调）：超出部分记录仍保存但 `gain=0`，并标记 `capped`；
- 时间回拨：记录 `lastTrustedAt`，当前时间比它早 2 分钟以上即拒绝计分并写异常；
- 兑换：先冻结、后扣分，状态机只允许 `pending → approved/rejected`，重复批准无效；
- 撤销：只能对已入账记录执行，退回 `gain`，且必须填理由（孩子可见）；
- 家长手动记账（`kind='manual'`）：家长端「积分」页每个孩子卡片可填分值（可正可负，如 `5` / `-10`）和一句理由，点「记录这笔积分变动」。**不受每日上限约束**，理由必填（孩子可见）；扣分最多扣到可用积分（`points - frozen`），冻结中的兑换积分不会被扣，0 分不记账。

### 3. AI 两段式预审

```
提交 → 规则预审（离线，永远可用）
        ↓
     模型可用？ → 是 → 模型预审（15s 超时，严格 JSON）
        ↓                    ↓
     规则结论           final = 更谨慎的一档（规则存疑不可被降低）
        ↓
   审核模式：全自动 / 混合 / 全部人工
        ↓
 入账 / 两栏待办（AI 建议通过、AI 存疑）/ 仅记录
```

- 模型失败、超时、返回非 JSON → `source=rule`、`participated=false`，家长端显示「AI 未参与（规则预审）」；
- 规则升级条件（硬编码）：重复提交、时间回拨、补交 > 48h、关键习惯无说明、单次积分 ≥ 阈值、首次提交、近 7 天完成率突增；
- 7 岁默认 `manual`，13 岁默认 `mixed`；可在「积分与奖励」里逐孩子切换；
- 孩子端四种状态：`已记录 / 等家长确认 / 家长已确认 / 需要补充说明`，不出现任何 AI 评价式措辞。

### 4. 同步事件

分机同步新增 `kind`：

| kind | 触发 |
| --- | --- |
| `habit_submit` | 孩子提交习惯（含补交标记、是否有说明/照片） |
| `review_needed` | 需要家长处理，孩子端停在「等家长确认」 |
| `habit_review` | 家长通过/驳回/撤销（带理由） |
| `review_result` | 结果落定（AI 自动入账或家长处理完） |
| `redeem_request` | 孩子发起兑换（积分已冻结） |
| `redeem_result` | 家长批准/驳回兑换 |

同步失败不影响本地流程；孩子端不会自行入账，仍显示「等家长确认」。`syncPayload` 同时带上 `points` 与 `habits` 摘要，旧字段 `tasks` 保留为习惯完成数。

### 5. 备份

「家长端 → 数据 → 导出备份」序列化整份 `state`，因此自动包含所有孩子（含已归档的）、积分、冻结、流水、习惯、奖励、兑换、异常与 AI 统计；仍然清空 `model.apiKey` 与 `sync.token`。**导入改为按 `childId` 合并**：不存在的孩子新增，已存在的孩子只补聊天/习惯/积分流水并去重，其他孩子完全不动；不会覆盖本机记录，重复导入同一份备份也不会让积分翻倍。

### 6. 本机测试

- 逻辑测试 59 项：默认库、迁移、提交/重复、上限、回拨、冻结/批准/驳回/重复批准、加时、规则硬约束、阈值/补交/首次升级、13 岁自动入账、撤销退分、准确率口径、周报、备份字段、禁用措辞。
- 界面测试 42 项：首页积分卡/今日习惯/补交、提交弹窗与照片入口、商城禁用态、家长端两栏待办、三档切换、习惯/奖励增删、模型参与/失败降级/规则约束、同步 payload、孩子端文案。
- 均使用 jsdom；真实 iPhone Safari 上的触感、文件选择器和长文本滚动仍需人工验一遍。

## 十五、多孩子与身份切换

### 1. 孩子怎么加

「家长端 → 孩子」页可以**无限添加**，每个孩子一份独立档案：

| 字段 | 说明 |
| --- | --- |
| 昵称 / 年龄 | 年龄只用来取语气档（≤8 / 9–12 / 13–15 / 16+），不再写死 7/13 |
| 头像 emoji | 首页头像条和聊天页显示这个 emoji |
| 4 位口令（可留空） | 留空则免验证切换；设了就必须输入正确口令才能切到这个孩子 |
| 每日时长上限 / 禁用时段 | 每个孩子单独计算，切换后立即按新孩子的规则生效 |
| 禁聊话题 | 在全家清单之外，这个孩子额外的禁聊词 |
| 习惯集 | 低龄集（生活自理）/ 少年集（学习与自管），决定新建时预置哪些习惯 |
| 积分账户 | 独立余额、流水、冻结与兑换记录 |
| 须知同意 | 每个孩子单独的开关；开启后家长只能看摘要，孩子可控制是否公开原文 |

「归档删除」会先弹两次确认，并明确提示会连带移除这个孩子的习惯与积分；确认后数据进入**归档区**（昵称、习惯定义、积分、聊天、记录都保留），随备份一起导出，不会静默丢弃。

### 2. 老数据怎么迁移

首次用新版本打开时，`loadState()` 会把旧的 `k7` / `k13` 两个档案补齐成新结构，**保留原 id、昵称、年龄、习惯定义、习惯记录、聊天、积分、冻结、兑换、隐私与备份字段**。迁移不重算任何记录（测试校验了迁移前后条数不变）。如果迁移过程抛错，程序不会写回，原数据原样保留，另存一份 `kids_ai_helper_v2_migration_backup`，并提示先导出备份。

### 3. 设备怎么绑、怎么切

- **设备绑定**：在「家长端 → 孩子」点某个孩子的「设为这台设备默认」。之后这台设备打开就进那个孩子的界面，优先级最高。分机场景一台设备只绑一个孩子。
- **一键切换**：首页常驻头像条，点一下就切，不用进设置。切换后聊天记录、积分、时长、习惯、审核待办都按新孩子重建，上一个孩子的对话不残留。
- **口令**：设了口令的孩子，切换时弹 4 位口令框，输错有提示；口令留空则直接切。
- **记住上次使用者**：同机轮流时默认回到上次用的人；可在「孩子」页关掉，关掉后每次自己选。
- **诚实说明**：小星**不做声纹识别、不做人脸识别，也不推断「现在是谁在说话」**。所谓「谁在用就切到谁」只靠设备绑定 + 一键切换 + 记住上次使用者。换人坐过来但没切换，程序不会知道。

### 4. 隔离与家长视图

- 聊天、积分、冻结、习惯定义与记录、审核待办、兑换、风险事件、每周报告、AI 预审统计全部按 `childId` 存储与渲染；A 孩子的记录不会出现在 B 孩子的界面。
- 家长端每个页签都有「全部孩子 / 具体孩子」筛选。**全部孩子只显示合计**（孩子数、今日发言、今日习惯、待审核等），逐人详情需要选中某个孩子查看；不提供排行榜，也不显示「谁更好 / 谁更优秀」。
- 同步 payload 顶层必带 `childId`，家长端可据此区分是哪台设备、哪个孩子；两台设备并发上报不会串。
- 备份导出包含所有孩子；导入按 `childId` 合并，只补不覆盖其他孩子。

### 5. 家长第一次要多做哪几步

1. 「家长端 → 孩子」核对默认两个孩子的年龄，不需要的归档删除、缺的新增。
2. 给孩子设头像与（可选）4 位口令。
3. 同机使用：决定是否开启「记住上次使用者」；分机使用：每台设备点一次「设为这台设备默认」。
4. 逐个确认「须知同意」开关与每日时长、禁用时段。
5. 如需分机，在每台设备填同步地址，并确认上报 JSON 里有 `childId`。
